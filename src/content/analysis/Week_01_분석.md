## 이번 주 핵심 발견

**AI를 쓰는 방법이 아니라, AI와 일하는 구조를 설계한 주.**

4명 모두 "AI로 무언가를 만들었다"는 공통점을 갖고 있지만, 주목할 점은 단발성 결과물이 아니라 **반복 실행 가능한 파이프라인**을 만들었다는 것이다. 한 번 쓰고 버리는 프롬프트가 아니라, 매일 돌아가는 워크플로우, PR마다 작동하는 리뷰 봇, 매주 실행되는 분석 명령어를 설계했다.

---

## 주요 트렌드

### 1. 자동화의 단위가 "작업"에서 "파이프라인"으로

모든 제출물이 단일 작업이 아닌 여러 단계를 연결한 파이프라인 구조였다. RSS 수집→요약→발송, PR diff→분석→코멘트, 프롬프트 생성→이미지 생성→가이드라인 작성 등. AI를 한 번 호출하는 것이 아니라, 데이터 흐름 안에 AI를 배치하는 패턴이 공통적으로 나타났다.

### 2. 비용과 품질의 트레이드오프를 직접 실험

여러 멤버가 API 비용 최적화를 직접 체감했다. 기사 원문 대신 첫 500자만 넣어 비용을 5배 절감한 사례, 파일별 호출을 PR당 1회로 줄여 rate limit을 회피한 사례 등. "더 많이 넣으면 더 좋다"는 직관을 데이터로 반증한 셈이다. 토큰 경제학을 이론이 아닌 실전에서 학습했다.

### 3. 도구의 한계가 아키텍처를 결정

카카오톡 비즈메시지의 템플릿 검수 규칙, Figma 플러그인의 레이아웃 깨짐, GitHub API rate limit 등 — 외부 도구의 제약 조건이 최종 설계를 좌우한 경험이 공통적이었다. "원하는 대로 만들기"가 아니라 "제약 안에서 최적 구조 찾기"를 체득한 주.

## 이번 주 독특한 시각

### "AI 디자인 도구의 진짜 가치는 최종 결과물이 아니라 탐색 범위를 넓히는 것"

대다수가 코드와 자동화에 집중한 가운데, 한 멤버는 Midjourney + Claude + Figma 조합으로 브랜딩 프로세스 전체를 재설계했다. 5분 만에 시안 5개를 확인하고 방향을 잡는 속도감, 그리고 "AI는 실행 속도를, 사람은 방향 설정을 담당하는 분업"이라는 관점이 인상적이다. 기술 도구를 비기술 영역에 적용한 유일한 사례.
